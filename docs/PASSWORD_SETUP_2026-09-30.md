# 首次密码配置与登录修复

交付版本：v0.3.0-rc8 · Build 13。

用户报告首次配置后浏览器无法使用刚输入的密码登录，同时指出错误提示未定位具体密码、缺少显示密码选项。本轮使用独立合成资料库检查，未读取用户密码，未修改日常配置、资料或已保存凭据。报告中的现场登录失败尚未复现，不能将发现的边界问题认定为现场原因。

## 调整

- 登录密码与保险库口令使用固定字段标签和用途说明，确认字段明确命名。错误紧邻字段，并自动切换设置页、滚动到错误位置；后台凭据错误带字段标识供窗口定位。
- 本机登录 / 保险库 / 恢复相关输入增加眼睛按钮；浏览器登录增加显示 / 隐藏按钮。离开应用或浏览器窗口后隐藏，不写入持久存储。
- Swift 的字符串相等比较会接受不同 UTF-8 编码的 Unicode 规范等价字符串；认证比较原始字节。本轮通过测试复现并将确认逻辑改为字节一致，不修改已有凭据。
- 拒绝新登录密码和保险库口令中的 CR / LF。浏览器密码框会删除这两类换行，见 [HTML 密码输入规范](https://html.spec.whatwg.org/multipage/input.html#password-state-(type=password))；不能保存用户无法在该输入框原样输入的密码。其他空白保留原样并提示，不自动裁剪。
- 保存并启动传递刚设置的登录密码给本机管理命令，使用标准登录接口实际验证，随后退出验证会话。只在验证成功后打开浏览器；失败停止该配置对应的服务并明确说明配置已保存、登录验证未通过。验证请求不使用系统代理、不跟随重定向，HTTPS 使用本机配置的 CA，不跳过证书校验。口令仅通过标准输入 / 请求体传递，不进入命令行和日志。

## 检查

- Swift 密码表单检查：首次必填、已有配置留空保持、两类确认分别报错、只有确认框输入也算未保存、长度、Unicode 字节差异、CR / LF 与首尾空格。
- 首次保存登录与保险库的接口检查：英文数字、中文、引号、组合字符、表情及首尾空格；保存后原样登录成功，保险库口令不能代替登录密码；验证结束的会话失效，重定向不转发密码。
- 新密码 CR / LF 在保存前拒绝，并指向正确字段；原有修改密码与事务保护测试继续执行。
- 本轮运行 `scripts/check.sh`：前端构建、18 项前端测试、Go vet、全套 race 与集成测试、11 项样本恢复检查。样本报告为 `reports/m0-20260930-203826.json`。其后增加的换行校验另跑相关包测试与 Swift 检查。
- `scripts/check-launcher.py` 使用随包服务与隔离目录检查首次设置、启动后实际登录、失败停止、修改密码、旧密码拒绝、崩溃重启、更新备份与重启。首次运行在崩溃重启后的 HTTP 检查遇到 503；测试机配置了代理，原脚本未隔离代理且只等进程存活。改为直连回环地址并等待认证接口准备好后，整套通过。该测试环境问题不作为用户密码失败的解释。

## 后续定位

若用户更新后仍无法登录，需要核对 App 所用资料目录、实际服务地址、网页是否自动填入旧密码，以及“保存并启动”的验证结果。只询问字符类型或截图中不含密码的状态信息，不索要明文密码。禁止擅自重置密码、替换数据库或重建资料库来掩盖问题。
