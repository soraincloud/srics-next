## 分类方式

六类资料按索引中的模块独立管理。磁盘采用随机编号对象，**并不是六个可直接按名称浏览的文件夹**：

```text
资料目录/
  index.db          分类、名称、标签、页序、章节正文、任务、受口令保护的保险库密钥
  objects/          漫画页、普通图片、个人照片及独立缩略图
  private-objects/  私密照片、个人文件及私密缩略图的 age 密文
  chunks/           未完成上传的分块；私密分块加密
  staging/          一致性快照与升级前保留的索引
  format            资料库格式与身份标识
```

保险库名称、原始文件名、分类和明文哈希在数据库中以加密元数据保存。普通空间名称和内容不是本地加密；restic 备份会加密完整资料库。

每本漫画有独立编号和有序页面列表。导入 `2.webp`、`10.webp` 会按自然数字排序，下载为 `漫画名称/00001.webp`、`00002.webp`。同名漫画和图片分别建项，不按文件名覆盖其他资料。重新新建任务导入相同文件会新增条目；同一任务的网络重试保持幂等。这不等于全库内容去重。

**长期备份必须包含索引、文件对象和受保护的保险库密钥，不能只复制 objects 文件夹。** 使用系统的一致性加密备份与恢复功能。普通原件可以独立识别格式，但名称和分类依赖索引；私密对象还需要原保险库口令解锁。日常导出可以得到具名文件和漫画 ZIP。

## 图像处理规则

| 入口与格式 | 原件处理 | 下载结果 |
| --- | --- | --- |
| 漫画：已有有效静态 WebP | 校验容器、尺寸和可解码性，原字节保存；包括原本有损的 WebP | 与上传文件逐字节一致 |
| 漫画：8 位静态 PNG / JPEG | `cwebp -lossless -exact -m 4`；转换后逐像素比对，失败拒绝入库 | 转换后的 WebP，后续重导不再编码 |
| 普通图片 | 校验支持的图像格式，保存原字节 | 原格式、原字节 |
| 个人照片 | 保存原字节；不支持预览的格式仍可下载 | 原格式、原字节 |
| 私密照片 / 个人文件 | 加密原字节；不进行原件图像转码 | 解密后与上传字节一致 |

判断 WebP 使用文件内容，而非仅看扩展名。校验时解码不会改写文件。漫画不接受动画 WebP / PNG、16 位 PNG 或不支持的图像，避免静默丢帧、降位深。当前漫画仍限制单页 64 MiB、4000 万像素及每边最多 16383 像素。

PNG/JPEG 转换的“无损”指**相对输入文件解码后的像素**；JPEG 原本已经丢失的信息无法恢复。转换会保留所支持的 ICC / EXIF / XMP 元数据，但不保证保留源容器的所有附加字段，也不另存原始 PNG/JPEG 文件。若需要档案级原始文件字节保留，应另存到个人照片或个人文件。已有 WebP 的元数据、未知块和填充也全部原样保留。

缩略图独立存储：普通空间生成最长边 640 像素的 JPEG 预览，私密照片生成加密 PNG 预览。普通图片有方向元数据时暂用原图预览。缩略图不会覆盖原件；漫画连续阅读、图片大图、私密照片大图和下载均读取完整原件。列表看起来不如原图清晰，不代表保存的文件变糊。

漫画 ZIP、恢复副本单项导出和 restic 备份路径复制原件或密文，没有图像编码步骤。归档、加密和备份压缩不属于有损图像转码。

## 本次验证

所有新增写入测试均使用独立临时资料库和合成图片，不修改演示库。

- 三份 WebP 样本各连续调用导入转换器 100 次：有损 / 无损、透明通道、带元数据和不带元数据；每轮全部字节及 SHA-256 相同，编码器路径故意不存在。
- 含 ICC / EXIF / XMP 的 WebP 在没有编码器时仍原样保留；提交的样本还覆盖未知 RIFF 块和奇数长度填充。
- PNG（含完全透明像素）和 JPEG 转换后逐像素一致，转换所得 WebP 再次导入原字节保留。
- 实际 HTTP 接口：两份 WebP 在漫画、图片、个人照片、私密照片、个人文件各执行 10 轮“分块上传 → 下载 → 用下载结果重新上传”，全部 SHA-256 和原始字节一致。漫画每本两页，检查自然排序和 ZIP 目录；错误扩展名仍按真实内容处理。
- 同一上传完成请求重复发送，原件不改写；同名新任务分别建项。检查分类数量、普通对象位置、私密原件加密及未进入普通对象区，随后执行回收与完整性校验。
- 普通三类空间实际生成独立 JPEG 缩略图后，WebP 原件字节及哈希不变；完整图片接口返回原件。
- 当前演示库只读检查：23 个被引用的普通原件大小及 SHA-256 正常，10 个私密密文对象（含缩略图）哈希正常，SQLite `quick_check` 通过。未解密私密原件；这项检查证明当前内容与索引一致，不能追溯没有留存的历史源文件。

针对性回归与并发检查：

```sh
go test -race ./internal/media ./internal/library ./internal/server -count=1
```

测试随仓库正常检查运行，无需手工执行。长期使用仍以独立设备上的加密备份和实际恢复演练为依据；本次检查不替代 100 GB 真正数据规模、磁盘故障或异机恢复验收。

## Markdown 文档补充（2026-10-03）

第七类文档的名称和标签保存在索引，UTF-8 Markdown 原文作为独立不可变对象保存于 `objects/`，不会经过图像转码。保存正文先原子写入对象，再更新索引引用与版本号；备份固定同一版本的索引与文件。恢复副本可直接导出 `.md` 原文，空正文也可保存和下载。文档属于普通资料，敏感内容仍使用个人文件保险库。
