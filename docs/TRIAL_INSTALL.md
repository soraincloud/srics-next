# SRICS Next 安装与使用

版本：v0.3.0-rc24 · Build 30。当前包：Apple Silicon（M 系列）Mac，macOS 27.0 或更新版本。

本机交付直接提供 `SRICS Next.app` 并在 Finder 中选中，不生成应用压缩包。当前应用位于 `dist/0.3.0-rc24-build30/SRICS Next.app`。Build 23 统一备份文件与恢复 JSON，Build 25 补齐开源许可和随包源码，Build 26 新增 Markdown 文档，Build 27 固定页面返回及阅读操作顶栏，并调整 Markdown 标签和正文留白；Build 28 统一网页密码输入同步和中文标点提醒，Build 29 统一内容最大宽度及顶栏对齐，Build 30 新增普通文件模块，并修复上传窗口重复选择同一文件的问题。变化见 [更新记录](../CHANGELOG.md)。

这是现有构建机生成的试用包。程序窗口本身以 macOS 13 为编译目标，但本包的服务和部分内置库要求 macOS 27；打包脚本现在会按全部内置组件的最高要求设置最低系统版本。旧系统需要另外构建兼容依赖的包，不能通过修改版本标记获得兼容性。

## 安装和首次试用

1. 把 Finder 中的 `SRICS Next.app` 拖到“应用程序”目录。
2. 打开程序。在新机器上选择资料存放位置、设置自己的登录密码；私密照片 / 文件需另设保险库口令。
3. 首次先使用“仅本机”，点击“保存并启动”，再点击“打开资料库”。本机浏览器访问不需要 HTTPS 证书。
4. 先上传少量测试资料，确认查看、下载和备份恢复可用，再逐步迁入正式资料。原始副本暂时保留。

同一台机器、同一个 macOS 用户会读取此前的配置和资料，不会生成一份空资料库；如果此前是演示环境，仍沿用演示配置。`.app` 只包含程序和运行依赖，不包含资料、口令或个人配置。将 `.app` 复制到其他机器不会迁移资料；已有资料通过备份恢复迁移。

## 两种证书的区别

- HTTPS 证书：仅在启用局域网 HTTPS 后，需要在访问设备上安装并信任程序导出的公共证书。先在本机试用无需安装。
- App 签名 / 公证：当前包为临时签名，已通过签名完整性检查，但没有 Apple Developer ID 签名和 Apple 公证。跨机器或从网络下载后，macOS 可能阻止首次打开。

若提示开发者无法验证，在确认这是本次交付的包后，可按 Apple 的说明，在尝试打开后前往“系统设置 → 隐私与安全性 → 仍要打开”。不需要购买或手动安装开发者证书。若提示损坏或包含恶意内容，应先停止并检查包的完整性，不要关闭系统保护。

Apple 说明：https://support.apple.com/zh-cn/102445

## 备份和更新

重要资料需要独立硬盘或云端的加密备份，并单独保存应急恢复 JSON。同一磁盘上的备份无法防止整盘故障。

停止服务并保存配置，App → 备份 → 开始设置。按“保存并验证恢复 JSON → 选择位置 → 创建第一份备份”操作。已有私密资料时，只在生成步骤验证保险库口令一次。之后无需准备口令文件、导入另一份凭据 JSON，或每次拿出恢复 JSON。所有新备份使用同一种 `.sricsbackup` 文件；修改密码、更换位置和首次启用私密区仍使用原 JSON。S3 账号访问密钥在表单中填写，程序内部保管。OneDrive 可直接选择其同步目录。旧仓库和旧 JSON 保留在兼容入口。完整说明见 [统一备份与恢复](RECOVERY_KEY.md)。

之后更新时，先在“版本与更新”点击“停止服务并准备更新”，等待备份与校验成功，完全退出程序，再用新版 `.app` 替换原位置的旧版程序。程序包之外的资料和配置会保留。Build 30 将资料库索引升级到版本 6，旧版程序不能直接打开升级后的资料目录；回退应恢复升级前的备份到新目录。

## 设置、修改与忘记密码

登录密码用于浏览器登录，保险库口令用于日常解锁私密照片与个人文件，分别设置与修改。原生隐藏输入使用英文直接输入；中文口令可先点眼睛显示后输入，或粘贴后核对。切换显示不会修改口令内容。恢复 JSON 只用于系统损坏或丢失时解密备份；不参与日常设置、修改或重设口令。

忘记登录密码时，在本机 App → 密码与保险库 → “重设登录密码…”，输入新密码并确认。该操作不要求旧登录密码，权限来自当前 macOS 用户对本机资料库的访问权限；会停止服务并退出已登录设备，但不修改保险库。没有网络重设接口。成功后重新启动服务。

修改保险库口令时，先停止服务，在“修改保险库口令”填写当前口令、新口令与确认口令，保存配置。该操作必须验证当前口令，不接受恢复 JSON 或登录密码替代；只重新保护原加密密钥，私密原件不重新编码、恢复材料不替换。历史备份保持原样。

忘记保险库口令时，不提供绕过旧口令的本机重设入口。进入独立的“从备份恢复”流程，用完整备份文件与匹配的恢复 JSON 取回资料，再配置恢复后的新资料库。只能取回备份中已有的内容，尚未备份的修改不在恢复范围内。

若旧版本设置时已发生丢字，更新不会自动改写已保存的密码。先用实际保存的旧口令解锁并修改；无法解锁时使用备份恢复，尚未备份的内容不能靠改密找回。

## 迁移资料目录

App → 服务配置 → 迁移与换设备 → “迁移资料目录…”。若有未保存更改，先保存；选择目标位置后，App 会自动生成一个新的子目录，点击“停止服务并迁移”。建议选择具有完整权限和持久化支持的 APFS 内置或外置磁盘，目标空闲空间需能容纳全部资料并额外保留 64 MiB，源盘也需要少量空间生成一致性数据库快照。

程序先停止后台服务，再保持源资料库独占锁，制作包含数据库、回收站、普通原件、私密密文、小说版本、恢复密钥记录及未完成上传分块的一致性快照。跨目录复制写入独立文件，逐个重新读取并比较 SHA-256，完成索引和原件校验后才原子切换配置。私密文件按密文完整性校验，不需要输入口令，也不更换保险库密钥。旧配置与校验记录保存在本机配置目录的 `migrations` 中。

迁移完成后点击“启动服务”，使用原登录密码和保险库口令。新位置正常解锁、浏览，并完成一次独立备份后，再自行处理旧目录。程序不会删除旧资料，不会覆盖已有目标；失败副本会保留，重试需选择新位置。若配置保存结果不明确，先刷新查看当前目录；两个目录都保留。迁移后的旧副本不会继续接收新修改。

备份仓库、云端凭据、恢复 JSON 外部文件、HTTPS 证书与 App 本体不属于资料目录迁移范围，仍在原处。用户手工塞进内部目录、没有导入系统的额外文件不属于受管理资料；应单独保管。

## 更换部署设备

1. 旧 Mac 停止编辑，完成最终统一备份，保管完整 `.sricsbackup` 和原恢复 JSON。
2. 新 Mac 打开同版或更新版 App → 从备份恢复，选择包、JSON 与导入位置，再恢复到新的资料目录，等待全部校验通过。无需先创建空资料库。
3. 可为恢复副本设置新密码，启用后抽查全部资料与私密原件。
4. 新 Mac 重新选择备份位置和云账号，继续使用原资料库 JSON；网络与自启按新机配置。新机验收并完成新备份前保留旧副本。

资料库数据库包含内容索引、标签、小说正文与版本、密码哈希、保险库密钥封装和恢复密钥记录，因此恢复不是只取回图片文件。`.app` 本身不含这些数据；单独复制 App 不会迁移资料。
