## 更新与存储边界

数据库升级到 schema 4，旧索引先以权限 600 保留在 staging。升级前的实际演示库已用旧版本创建并完整校验加密快照，旧 `.app` 单独保留。旧程序回退需恢复升级前快照到新目录，不能直接读新 schema。

回收站清理是逻辑删除与文件回收，不是安全擦除；已有历史备份由独立保留策略管理。迁移索引不自动删除。完成加密备份才是独立恢复依据。单项取回当前先恢复完整快照，而且再次检查恢复副本，取回少量文件仍可能读取较多数据。

备份保留按最近有快照的 UTC 日期分组，每组取最新快照；每日与月度候选取并集。删快照后 prune 回收数据，失败会显示清理错误并允许重试。实现参考 [restic 删除与清理文档](https://restic.readthedocs.io/en/stable/060_forget.html)。
