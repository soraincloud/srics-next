# M0：工程骨架与恢复验证

日期：2026-09-19。此阶段交付一个可运行的本机验证版，证明选定的存储、加密、转码和恢复路径可以连接起来。六类业务入口展示已确定的功能范围，尚不接收真实资料。

## 已实现

- Go 主程序内嵌 Vue 3 构建产物，提供概览、验证中心、模块范围和开发进度。页面可发起真实验证、查看逐项进度并下载 JSON 报告；没有模拟的文件数量和存储统计。
- 通过 libwebp 的 `-lossless -exact` 转码。PNG/JPEG 先使用 Go 解码器得到统一的 NRGBA 像素，再编码并重新解码逐像素比对；完全透明像素的 RGB 也参与检查。
- ICC、EXIF 和标准 XMP 与像素分开保存。当前不应用色彩变换或 EXIF 旋转，保留方向信息，避免像素旋转与元数据方向重复作用。JPEG 本身已损失的细节不能恢复。
- 已有可解码的静态 WebP 保留原字节。拒绝动画、16 位 PNG、无法识别的输入和超出尺寸 / 像素预算的图片。M0 输入上限为 64 MiB，解码上限为 4000 万像素，且不超过 WebP 单边 16383 像素限制。
- age X25519 文件加密；独立 scrypt 口令包装私钥；私密名称、校验值和对象绑定信息作为密文存入 SQLite。私密源内容直接写入加密流，不先创建明文临时原件。
- 文件先写入 0600 临时文件，刷盘后以不覆盖已有路径的方式发布，再提交索引。同名内容使用不同随机编号。名称与物理路径分离，普通 / 私密存储域分离。
- SQLite WAL + FULL 同步，使用 SQLite Backup API 取得索引快照。M0 保守地持有写锁并复制快照引用的不可变对象；M1 将改为固定版本引用、缩短锁持有时间。
- restic 本地测试仓库的初始化、加密备份、全量数据读取检查、指定快照恢复与恢复后的验证。备份进程不接收保险库口令；已有恢复目标一律拒绝覆盖。
- 仅监听回环地址；限制 Host、Origin、跨站请求和变更请求头。响应不缓存，不提供任何真实资料访问接口。

## 可复现验证

```sh
./scripts/check.sh
```

该脚本依次构建前端与 Go 程序，运行 `go vet ./...`、`go test -race ./...`、恢复集成测试，以及 CLI 的完整验证。所有步骤有独立失败退出状态。并发测试与前端构建需按顺序执行，避免前端清理产物目录时与 Go embed 同时读取。

CLI 与页面使用同一个验证实现。每次生成新的随机测试口令、私密内容和私密名称，只在本机临时目录创建样本；不传输到云端，不使用用户照片或旧系统数据。完整验证包括 11 项：

1. 检查 cwebp / restic 实际可运行及版本。
2. PNG（含透明像素）和 JPEG 无损往返；EXIF 方向及合成 ICC 数据逐字节核对。
3. 原有 WebP 字节保持、自然数字排序；坏图、16 位及动画 PNG 拒绝。
4. 加密内容往返、受口令保护的私钥文件。
5. 错误口令、篡改、截断和未解锁读取拒绝。
6. 普通对象、私密对象及加密索引的写入和取回。
7. 扫描测试目录内文件（包括 SQLite / WAL），检查测试私密名称、内容、私钥和口令未以明文出现。
8. 建立 SQLite 一致性快照，确认快照不包含之后的新写入。
9. 不提供保险库口令的 restic 加密备份。
10. `restic check --read-data` 读取并校验全部测试备份数据。
11. 关闭数据库，移除本轮工作目录与快照目录，再仅凭备份和独立测试口令恢复到新目录；核对索引范围、普通原件、私密名称和私密内容。

测试还覆盖并发写同一路径只有一个成功、写入失败不发布、同名文件不覆盖、元数据互换拒绝、数据目录缺失不自动创建、恢复不覆盖已有目录、错误备份口令拒绝、重复验证任务拒绝以及 HTTP Host / Origin 边界。

本机已通过前端 TypeScript / Vite 构建、Go 并发测试、静态检查、restic 集成测试和 11 项完整恢复验证。一次可追溯的 JSON 结果放在 [verification/m0-darwin-arm64.json](verification/m0-darwin-arm64.json)。界面在应用内浏览器检查桌面和 390px 手机布局，实际点击验证按钮完成了 11 项检查。当前 Chrome 环境会阻止该本机地址，应用内浏览器可以访问；没有修改 Chrome 安全设置。

## 使用方式

构建：`./scripts/build.sh`。首次构建需要 Go、Node.js 和 C 编译工具链（SQLite 使用 cgo）。运行：`./start.command` 或 `./bin/srics serve`。构建之后运行无需 Node.js，cwebp / restic 仍需本机已安装。

验证：`./bin/srics verify`。保存一份新报告：先创建 `reports` 目录，再执行 `./bin/srics verify --report reports/example.json`。命令不会覆盖已有报告。点击页面“下载验证报告”也能保留结果；服务重启会清空内存中的最近一次报告。

默认地址：`http://127.0.0.1:19473`。停止运行：终端 Ctrl+C；正在运行的外部任务会收到取消信号并清理该轮临时数据。M0 不注册后台自启服务，不创建真实数据目录。

## 当前边界与下一步

这是技术验证，不是生产环境的安全验收。合成明文扫描不能证明任意输入、内存、交换区或受控制主机没有泄漏；Go 内存回收也不提供私钥绝对清零保证。底层包是内部实现，只有小样本读取接口，当前没有大文件流式下载与各设备解锁会话。

元数据验证检查的是保留字节及固定解码规则下的像素一致；跨浏览器的 ICC 色彩呈现、EXIF 方向显示、扩展 XMP 等更多元数据组合仍需 M2 的真实格式测试集验证。M0 暂拒绝带压缩 XMP 的 PNG，不能静默丢弃这类元数据后宣称完全支持。

快照复制方式适用于此阶段的小样本证明；尚未完成 100GB 规模性能、空间不足、进程崩溃、磁盘拔出和后台任务续传测试。数据库格式带 M0 版本标识，后续正式格式升级需迁移，不能将验证格式当作稳定发布格式。

下一阶段 M1：单用户登录与会话、部署数据盘身份检查、可迁移的正式数据模型、持久化上传任务和失败恢复、回收站、最小备份状态。其后按开发计划完成全部六类业务。局域网 HTTPS、自动锁定、原生发布包、依赖随包交付、独立硬盘 / 云端备份和完整恢复验收尚未交付。

技术依据：[libwebp 编码选项](https://developers.google.com/speed/webp/docs/cwebp)、[age Go API](https://pkg.go.dev/filippo.io/age)、[SQLite Backup API](https://www.sqlite.org/backup.html)、[restic 恢复说明](https://restic.readthedocs.io/en/stable/050_restore.html)。
