# 图片、照片与实况照片

2026-10-14，v0.3.0-rc30 · Build 36。既有资料不批量改名或转码。

漫画与普通图片中的静态收藏使用无损 WebP，并核对解码像素。已有静态 WebP 保留原字节；普通图片中的 GIF 继续保留全部动画原件。新增 HEIC/HEIF、AVIF、BMP、TIFF 的 macOS 解码入口。只有可确认的普通静态、8 位及以下内容允许转为 WebP；高位深、多图像、HDR 辅助图像、人像深度图以及已识别的动态照片会拒绝转码，提示存入照片模块。转换保留支持的元数据，不等于档案级原文件保真。

个人照片与私密照片保留原件字节，包括原格式、色彩配置、HDR/深度等附加数据。HEIC 等格式用独立预览浏览；预览最长边 2560，列表预览最长边 640，下载不读取预览。JPEG/PNG 的方向也由原生解码器处理，生成的预览方向标记归一为 1，避免二次旋转。预览显示效果不代表原件被降位深或改写。

## 实况照片

从 Apple 照片应用“导出未修改的原片”，同时选择同名照片和 `.MOV` 视频上传。按文件名配对为一条资料；遇到重复候选或缺少照片时明确报错，不猜测配对、不丢弃视频。只有 HEIC 时作为静态照片保存，程序不能生成没有上传的视频。

暂停、刷新或锁定后，可通过“选择照片与视频继续”重新选择同一对原件，只发送尚未保存的分块。配对忽略文件名大小写，并统一 Unicode 编码比较；容器内仍保留两份原始文件名。

每条实况照片的原件是一个不压缩的 `.livephoto.zip`，包含原始照片和原始 MOV，成员名称、字节和视频内的声音均不改写。此容器是资料导出格式，不是新的备份格式；备份仍只有 `.sricsbackup` 与原恢复 JSON。私密实况容器与预览均加密保存。

查看时可切换“静态照片 / 动态画面”。视频使用原 MOV，实际播放能力取决于浏览器对原编码的支持；无法播放时提供下载原件提示。系统按同名文件配对，不自动修复或重写 Apple 配对身份。原 MOV/照片中的身份字段保留，恢复后的 Apple 软件如何识别仍需实际设备验收。安卓动态照片附加的视频保留在照片原件内，目前不单独解析播放。

## 安全和恢复

原生 ImageIO 工具只用标准输入/输出传递图像，无明文临时文件；私密浏览随保险库锁定取消请求、清理缓冲及浏览器 Blob。单张原件仍最多 64 MiB，实况照片两部分连同容器合计最多 64 MiB；解码预算仍为 1 亿像素。原生解码串行执行，设输出大小及超时限制。

实况容器只接受两个不压缩、普通文件的条目，校验路径、大小、内容类型、配对名称与 ZIP CRC，拒绝额外成员、压缩炸弹、越界名称和损坏内容。进入 ZIP 解析器前将中央目录限制为 4 KiB，核对实际位置和两个成员的声明，拒绝分卷、ZIP64、归档注释及加密成员，避免异常元数据触发大量分配；这一限制仅作用于实况容器，完整备份包继续支持 ZIP64。上传依旧使用已校验的分块续传；配对容器确定性生成，重新选择相同原文件可恢复同一上传。

原件容器、加密对象、索引中的实况标记与预览沿用现有快照、垃圾回收、导出及备份路径。私密标记只存在加密元数据中；数据库结构与恢复 JSON 格式不变。独立临时资料库验证 HEIC/AVIF/BMP/TIFF、原件下载、动态视频、锁定拒绝，以及删除来源资料库后从真实加密备份恢复并逐字节比对。

格式依据：[Apple 原片导出](https://support.apple.com/guide/photos/export-photos-videos-slideshows-and-memories-pht6e157c5f/mac)、[WebP 规范](https://developers.google.com/speed/webp/docs/riff_container)、[ImageIO 缩略图方向](https://developer.apple.com/documentation/imageio/kcgimagesourcecreatethumbnailwithtransform)。
