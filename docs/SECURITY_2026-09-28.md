# 2026-09-28 安全与长期保存检查

检查版本：0.3.0-rc3，基于 `91f123b` 的修复。本机 macOS 27 / Apple Silicon。部署目标：一台独立 Mac，加云端加密备份。

后续复查又发现并修复了数据库截断后的空库初始化风险、恢复密钥临时文件残留和配置密码部分提交问题。**请使用 rc4 或更新版本**；具体复现与修复见[第二轮检查](SECURITY_RECHECK_2026-09-28.md)。本报告为第一轮记录，不能理解为 rc3 已排除全部数据丢失风险。

## 结论与边界

本轮发现并修复了原件读取校验缺口、慢请求占用登录锁、长期运行的证书续期缺失，以及依赖中的已知安全问题；同时补强了异常索引下的清理保护和 macOS 写入持久性。测试结果支持继续验收，不能证明不存在未知漏洞或所有硬件故障都能恢复。

**当前试用部署还不能作为重要数据唯一的保留方案：云端未启用，现有备份与资料在同一文件系统，尚未生成正式恢复密钥。** 在目标 Mac 上完成真实云备份、独立保存恢复材料，并在空环境中恢复成功之前，保留原始副本。

软件可以成为唯一的日常管理入口，重要内容仍需有独立副本。备份成功与“永不丢数据”不同：每日备份可能丢失上次成功备份之后的新增或修改；停机、断网或备份失败会扩大这一时间窗口。

## 本轮修复

| 问题 | 修复与验证 |
| --- | --- |
| 普通原件下载、原图预览和 ZIP 导出只检查存在或大小，不能识别同大小的内容损坏 | 原件预览和单文件下载先对完整文件核对大小及 SHA-256，Range 请求也不例外；使用同一已打开文件描述符。ZIP 逐项核对实际输出的字节，错误时中断响应，不完成 ZIP。恢复导出失败时不发布成品。新增同大小篡改、Range、ZIP 和文件替换测试。 |
| 不完整的登录请求在读取请求体时持有全局登录锁 | 将网络读取移出登录锁，设置请求体总时限与空闲时限，上传大文件按大小分配时限。被拒绝但尚未读取的请求体也有截止时间；私密区锁定不会被读取超时的续期覆盖。新增停滞 socket、并发登录及拒绝请求测试。 |
| 服务持续运行时，内存中的 HTTPS 证书不会更新 | TLS 握手时按日检查，临近到期自动续签服务证书并沿用现有 CA。失败时仅允许继续使用仍有效的缓存证书；过期证书拒绝服务。并发真实 TLS 握手验证续期和信任根不变。根 CA 仍有到期日，需要届时重新配置设备信任。 |
| 合法 JSON 但无效的文件引用可能被当作正常索引继续处理 | 读取普通条目、上传记录和私密文件引用时验证必要结构；GC 在删除前检查 SQLite 结构、外键和所有引用。异常时停止清理，保留现场。新增清理失败时连孤立对象也保留的回归测试。不能检测任意语义正确的恶意数据库改写。 |
| macOS 常规 fsync 的持久性弱于驱动器缓存刷写 | 不可变文件、配置和证书写入采用 F_FULLFSYNC；SQLite 每个连接启用 fullfsync 与 checkpoint_fullfsync，连接重建后仍生效。维持 WAL / FULL synchronous、不可覆盖发布和目录同步。设备、控制器及文件系统仍须正确履行同步语义；这不替代实际断电验收。 |
| Go 1.26.5 的标准库有 6 项扫描可达的已知漏洞 | 升级到 Go 1.27.1，并将 x/crypto 更新到 0.56.0。 |
| 系统 restic 0.19.1 的依赖仍有已知问题，单独扫描主程序无法覆盖 | 对 upstream 0.19.1 源码扫描后发现 3 项可达漏洞，另外有未调用的包或模块问题。固定源码校验值，以修复后的依赖重建随包 restic（包括 grpc 1.83.2、x/crypto 0.56.0、x/net 0.58.0、x/text 0.42.0、compress 1.19.2、otel 1.44.0）。不修改 restic 源码和仓库格式；不替换系统 Homebrew。依赖清单和许可证随包保存。 |
| 服务退出时，停滞连接可能超过优雅退出时限 | 请求继承服务退出上下文，优雅停止超过 5 秒后关闭剩余连接，避免继续等待客户端输入。 |

Go 漏洞编号：GO-2026-6218、6090、6089、6088、5972、5026；restic 初始源码扫描可达项：GO-2026-6348、6061、5970。扫描结果是调用分析，不代表已证明这些漏洞在本部署中的每一个利用条件都成立。

## 已检查的现有机制

- 访问边界：所有资料 API 需登录；会话 cookie 为 HttpOnly / SameSite Strict，HTTPS 下为 Secure；写操作有 CSRF 校验，Host / Origin / 跨站请求受限制。上传的主动文档作为附件取回，未直接作为同源 HTML 执行。
- 私密区：独立口令、会话级解锁、闲置锁定；文件和名称使用 age 加密；私密下载先核对密文及明文完整性。锁定取消请求并撤销网页 Blob URL。服务端解密仍依赖可信 Mac；不能抵御已控制该 Mac 或已解锁浏览器的攻击者。
- 写入与删除：原件不可变，分块核对哈希，重试与完成有幂等处理；文件先落盘再提交引用。删除先进入回收站；自动过期与备份历史清理为可选项。资料盘、索引或仓库缺失时不创建空替代库假装成功。
- 备份一致性：在变更锁下用 SQLite `VACUUM INTO` 取得一致索引，硬链接固定对应的不可变原件、私密密文和续传分块；验证后交给 restic。成功后执行完整 `check --read-data`。校验失败不进入自动历史清理。
- 恢复：还原到全新目录，不合并覆盖工作库；核对索引与对象后才允许切换。恢复密钥同时提供备用 restic 解锁方式与对应保险库私钥的加密封装；旧快照是否覆盖该密钥需要按恢复点判断。
- WebP：已有 WebP 原样保存，多轮导入下载字节一致；非 WebP 漫画按既定解码规则无损编码，转换后核对像素；缩略图与原件分开。个人照片、私密照片和个人文件保留原字节。

备份包含 SQLite（名称、标签、小说章节、修订、设置、受口令保护的保险库密钥、恢复密钥封装）、普通对象、私密密文、续传状态和分块。备份不等于单个 ZIP；必须完整保留 restic 仓库，不能只取 `snapshots/` 或删除看似年代久远的数据块。

## 独立 Mac＋云端的正式验收条件

1. **目标 Mac**：使用直连、本地 APFS 存储，足够容纳原件、上传分块、数据库快照与恢复副本；开启 FileVault、系统更新和独立账号，验证重启后服务启动以及睡眠对备份的影响。当前自启使用登录用户的 LaunchAgent，FileVault 解锁和登录前不会运行，断电重启后不能假设已经恢复服务。局域网 IP 建议在路由器上保留；地址变化导致无法绑定时需重新配置。不要把唯一数据库放在 SMB 或由网盘同步的目录。稳定电源和 UPS 能降低中断风险，仍不能替代副本。
2. **云端真实备份**：正式口令替换试用口令；配置真实 S3 目标并完成一次完整备份 / 读取校验。确认最后成功时间会持续更新，故意断开连接确认失败能被发现。当前没有外部邮件 / 推送告警，不能在长期无人查看状态时假设失败有人通知。完整读取检查会下载备份数据，需核对服务商的流量与请求费用。
3. **防误删与账号隔离**：云端开启适用的历史版本或不可变保护，Mac 上的备份凭据不应能永久清除历史版本、关闭保护或修改其生命周期。云管理账号与二次验证恢复材料另存。仅启用加密不能阻止持有云凭据的人删除密文。
4. **保留策略**：通过 restic 管理快照保留，不给仓库的当前对象设置“超过 N 天自动删除”的云生命周期规则；新快照可能引用很旧的数据块。历史版本保留也需要覆盖发现故障并完成恢复所需的时间。Object Lock 和锁文件 / prune 的兼容性必须按具体服务商验证，不能直接套用任意设置。
5. **恢复材料**：在云目标上生成、重新选择验证并完成备份的恢复文件，至少另存到与 Mac / 云账号独立的离线位置；同时保留云服务名称、端点、区域、bucket / prefix、账号恢复方式及安装包。云凭据可以通过独立管理账号重新签发；恢复密钥不能替代登录云服务的权限。
6. **空环境恢复**：在另一台 Mac 或干净环境中，只使用云端备份与独立恢复材料，恢复到新目录；普通文件比较哈希、小说核对章节、私密文件实际解密打开，并测试新密码。通过后再决定删除其他机器上的原副本。之后定期重复，重要批量导入后先做即时备份。

用户尚未指定云服务商，本轮没有修改云账号、创建收费资源或验证真实云权限。独立 Mac＋云备份能覆盖部分单机损坏场景；若需要覆盖云账号丢失、供应商异常与同时被误删，建议再保留一份周期性的离线副本。任何单一在线系统都不能承担无条件的永久保存承诺。

真实断电 / 拔盘、目标 Mac 的重启与设备证书信任、100 GB 真实规模以及跨设备界面操作仍需部署验收。本包为本机临时签名，未做 Apple Developer ID 公证。本轮没有重新进行浏览器逐页人工验收。
