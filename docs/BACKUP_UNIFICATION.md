# 统一备份与恢复（实施记录）

目标：用户只保管一种 `.sricsbackup` 加密备份文件和一份资料库恢复 JSON。登录密码与保险库口令保持独立，JSON 只用于灾难恢复。

- 恢复 JSON 按资料库生成，不再绑定本地 / 云端仓库。采用 age X25519 恢复身份；程序只保存公开接收地址，秘密仅导出到用户选择的 JSON。
- 自动备份、网页立即备份、App 手动保存、更新前保护共用同一个创建 / 校验 / 发布流程。内部 restic 仓库用于生成快照与去重，由程序管理，不作为需要用户保管的第二种产物。
- 每份包封装内部仓库的加密密码，使用恢复公钥保护。库内保险库身份同样由恢复公钥封装，因此启用私密区或修改日常口令不会要求另一份恢复 JSON。
- 位置只决定同一份包保存到本地目录 / 外置磁盘 / 网盘同步目录或上传到 S3。S3 账号凭据在表单输入后由程序内部保管，不要求导入另一份 JSON。
- 首次配置按“保存恢复 JSON → 重新选择并验证 → 选择位置 → 首次备份”推进。日常界面只显示恢复钥匙状态、备份位置、定时、立即备份与结果。
- 恢复默认只需选择包、匹配 JSON 和恢复位置。旧仓库、旧 JSON、旧备份包保留在明确的兼容入口，不自动删除或覆盖，不自动迁移真实用户配置。
- 保留多个日期版本；完整包需要额外空间，云端上传必须完成读回校验才记录成功。失败不覆盖已成功备份，也不清理历史。

验收必须覆盖：一份 JSON 跨位置与内部仓库变更；首次启用私密区、修改登录 / 保险库口令；原机 / 配置 / 日常钥匙全部删除后的六类资料恢复；错误 JSON、损坏包、取消、离线磁盘、云端上传与读回失败；旧格式仍可恢复。测试使用隔离合成资料，不改变用户正在使用的资料库。


实施结果（v0.3.0-rc18 / Build 23）：

- 完成统一管理命令、后台服务与调度器、原生向导 / 另存 / 恢复、网页状态与文件历史。新版 JSON v2 / 包 v2 保留 v1 兼容。
- 已通过六类资料与私密原件的整机丢失独立进程恢复；同一 JSON 跨仓库、密码变化和未来启用私密区；S3 完整读回、不覆盖、错误权限与损坏测试。
- App 隔离资料库完成另存、Finder 定位、包导入与恢复；网页完成立即备份与历史文件检查。真实资料库与配置未自动迁移。
- 新文件保留全部日期版本。旧版 restic 保留规则只作用于旧版入口；内部缓存只在全部目标完成后整理，不删除已发布文件。
- 首次设置是从旧模型切换到新模型的显式操作，不会静默生成另一把已验证的钥匙。旧 JSON 继续用于旧备份，不能直接视为 v2 钥匙。
