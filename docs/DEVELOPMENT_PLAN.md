[FEATURES.md](FEATURES.md) 定义七类功能。本文件补充开发顺序、默认行为和上线验收；不减少用户提出的任何核心功能。后续新增想法先记录，完成这一版后再评估。

**业务模块为漫画、小说、Markdown 文档、图片、个人照片、私密照片和个人文件。**

| 模块 | 必须交付的使用流程 |
| --- | --- |
| 漫画 | 上传文件夹 → 设置名称和标签 → 列表看第一页 → 名称 / 标签搜索 → 阅读 → 下载整本 ZIP |
| 小说 | 新建并命名 → 设置标签 → 新增 / 修改 / 删除 / 排序章节 → 名称 / 标签搜索 → 阅读模式 |
| 图片 | 上传 → 列表或随机照片墙 → 查看大图 → 下载 |
| 个人照片 | 原文件上传 → 简单列表 → 自动纳入备份 → 取回原件 |
| 个人私密照片 | 解锁 → 上传 → 列表或随机照片墙 → 查看 / 下载 → 自动锁定 |
| 个人文件 | 解锁 → 上传并命名 → 名称搜索 → 下载 / 删除 / 恢复 |

每一类使用独立导航和数据范围。公共能力只提供登录、上传任务、加密、回收站、备份与设置。漫画和小说共用标签组件；三个照片 / 图片入口共用画廊组件，但查询、随机池和访问权限严格按模块隔离。

**以下默认值用于直接推进开发。**

| 事项 | 第一版约定 |
| --- | --- |
| 部署 | 暂以 Mac mini / Apple Silicon 为开发和首版打包基线；最终主机在真实部署前核实。浏览器访问，桌面和手机自适应。 |
| 运行结构 | Go 主程序内嵌 Vue 3 页面；SQLite 保存结构化数据；文件存本地磁盘；随发布物交付 restic 与 libwebp 所需能力。 |
| 漫画输入 | 一目录一本，以目录名作为默认名称；页序按文件名自然排序。发现嵌套目录、坏图、重名冲突时明确列出，不静默漏页或覆盖。 |
| 漫画预览 | 列表中的预览就是该漫画的第一页；缩略图是可重新生成的展示副本，原件单独保存。 |
| WebP | 已有有效静态 WebP 保留原字节；受支持的 JPEG / PNG 漫画页与普通图片无损转换。普通图片的 GIF 原字节保存并混合展示；个人照片及私密文件保留原件。无损定义及限制见 FEATURES.md。 |
| 小说正文 | 首版纯文本，章节标题与顺序单独保存；手动保存和自动保存都必须等服务器确认。默认保留每章最近 20 个可回退修订，自动保存修订采用合并策略避免每次键入都创建版本。 |
| 搜索 | 漫画 / 小说按显示名称搜索，个人文件按名称搜索；名称包含匹配，多个标签默认全部满足。 |
| 随机浏览 | 每次进入建立当前模块的随机顺序，分页继续；同轮不重复。换一批重新打乱；本轮新上传内容下一轮再加入，已删除内容立即跳过。 |
| 私密范围 | 个人私密照片与整个个人文件模块默认加密，共用保险库解锁入口；服务端按各设备会话单独校验解锁权限，一台设备解锁不能让其他未解锁设备获得访问。 |
| 自动锁定 | 默认 10 分钟无前台操作后锁定，可修改。备份、后台任务和图片预加载不自动延长解锁时长；重启后锁定。 |
| 回收站 | 默认 30 天；明确区分当前库删除和历史备份保留。私密回收站仍需解锁。 |
| 云存储 | 本地开发先接测试备份目录；真实云服务商、地域和凭据在上线前选定。OSS / B2 仍是候选，并非已配置。 |

云供应商与最终主机的选择不阻塞本地代码开发；这是对 FEATURES.md B02 中“在实施前选定”的时间点澄清。联网部署、加密卷重启后的解锁方式和访问设备的 HTTPS 证书信任配置，需要在真实部署时验证。

**几项数据规则必须从底层实现。**

1. 上传成功表示原件已可靠写入且索引已提交；备份成功是另一个状态。完成状态只由服务端确认，重试使用稳定任务编号，不能重复创建条目。
2. 漫画导入在全部有效页面确认后才整体完成；用户处理坏图或明确排除文件前，保持待处理状态。文件夹来源内容不会被自动删除。
3. 私密上传的分块和临时内容必须加密暂存；锁定后暂停需要解锁权限的操作，再次解锁才可继续。锁定与后台预览、下载、名称搜索之间的竞争必须有测试。
4. 普通文件与私密文件使用独立存储域；不通过跨域去重共享明文对象。内部编号是稳定引用，显示名称和磁盘路径分离。
5. 私密名称、原始文件名、备注及预览密文可保存在数据库或文件中，但明文不得写入普通索引、WAL、日志或持久化缓存。服务端解密模型依赖可信主机，不承诺防御已被控制的主机。
6. 小说保存采用修订号检查；自动保存失败时保留当前编辑内容并显示失败。删除章节先进入回收站，正文、顺序和修订记录一起备份。
7. 备份生成数据库一致性快照并固定引用的不可变文件版本；备份期间禁止清理这些版本。只有完整快照成功才更新“已备份”状态，索引检查、数据读取校验与恢复演练分别记录。
8. 登录密码、保险库口令、备份解密材料分开管理。重置登录密码不能绕过保险库；恢复材料独立保存。修改保险库口令时必须说明历史备份仍可能由旧口令解锁，不能承诺追溯撤销旧副本。
9. 安装、升级和恢复是三个独立操作；升级前备份，恢复默认写新目录，数据格式不兼容时停止而非覆盖。旧 SRICS 迁移采用复制和校验，完成恢复演练后再切换。

**开发时先准备这些验证样本。**

| 样本 | 验证目的 |
| --- | --- |
| 00001.webp、00002.webp、1.webp、2.webp、10.webp；含缺号和重名候选的目录 | 数字排序、稳定次序、第一页封面、重复与缺页处理 |
| 透明 PNG、带方向 / 色彩信息的 JPEG、坏图、未支持位深与动画 | 无损像素与元数据规则、错误提示、不静默降级 |
| 同名普通文件、同内容不同名、断网重传和服务重启 | 不覆盖、不重复登记、任务恢复和校验值一致 |
| 两个浏览器同时编辑同一小说章节，保存中断网 | 版本冲突、保存状态、正文恢复和章节顺序 |
| 一个已解锁设备、一个未解锁设备；锁定时仍有预览 / 下载任务 | 私密访问权限按会话隔离，锁定后不继续授权读取 |
| 新建空数据目录、测试备份及独立测试恢复材料 | 七类内容、索引、名称、标签、章节、页序和密钥恢复 |

测试只使用合成素材和测试凭据；真实照片、恢复码、私钥、数据库、备份仓库不进入源码仓库。开发阶段可以用临时目录验证备份流程，但它不计为生产环境的独立备份。

**开始开发与开始存放真实敏感资料采用不同完成条件。**

现在可以开始 M0 和 M1：功能入口、数据格式目标、开发顺序和默认行为都已具备。真实使用前还需通过隐私与恢复测试，落实云端 / 独立硬盘副本，并验证不依赖原主机的恢复材料。

上线前需要核实的仅是实际部署设备与数据盘、云备份目的地与费用、恢复材料保存位置及设备证书信任方式；这些属于部署配置，不需要继续扩充功能清单。
