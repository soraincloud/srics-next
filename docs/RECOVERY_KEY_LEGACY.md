# 旧版恢复钥匙与仓库（Build 22 及以前）

仅供恢复旧备份时参考；新设置请看 [统一备份与恢复](RECOVERY_KEY.md)。

# 独立恢复密钥

0.3.0-rc2 起，部署 App 的「备份设置 → 恢复密钥」可为每个备份仓库生成独立应急恢复文件。它仅用于系统损坏或丢失后的备份解密恢复，即使旧密码也丢失，仍可取回备份中的资料。日常登录密码与保险库口令独立设置；保险库改密验证旧口令，JSON 不参与日常密码管理。

**完整且未损坏的备份仓库＋已在该仓库验证启用、且覆盖所选恢复点的完整恢复 JSON 文件，可以恢复该快照保存的全部六类资料，包括私密照片与个人文件。无需旧机器、旧配置或上述三种日常密码。** 保存的是整份 JSON，不是界面显示的密钥编号、指纹或文件名。持有这两样的人也能解开私密内容，因此恢复文件应与备份分开离线保管。

“备份”指完整 restic 仓库，包含 config、keys、snapshots、index、data 等仓库内容；只保留一个快照描述文件不够。若整个仓库已下载到本地，恢复不依赖云账号；若备份还在云端，仍需云账号或存储访问凭据将它取回。恢复文件不能替代云账号权限，也不能重建被永久删除或损坏的备份。

恢复密钥为灾难恢复提供独立解密途径。降低文件丢失风险，还需要持续成功的独立备份、历史版本保留和恢复演练。不要把“恢复文件已验证”理解为此后每次备份都成功，或任何硬件故障都能恢复。

## 设置

1. 停止服务并保存资料库配置，进入「备份设置」，打开云端或独立硬盘备份向导。
2. 选择备份位置。新仓库自动生成并管理独立加密钥匙；已有仓库沿用已保存钥匙或导入原备份密码 / 旧版口令文件。程序不会用新钥匙覆盖已有仓库。
3. 保存并创建备份，等待完整读取校验通过。
4. 进入「保存恢复钥匙」。启用私密区时输入现有保险库口令，仅用于建立私密资料的应急恢复能力，不修改口令、不把口令写入 JSON。
5. 点击「生成并保存 JSON」，选择独立位置。文件不能位于资料库、备份仓库或程序配置目录内；不会覆盖已有文件。
6. 重新选取已保存的 JSON。程序添加独立备份解锁方式，验证私密索引、原件和预览，创建包含恢复记录的新备份，并使用恢复密钥执行完整读取校验。全部通过后才能在向导中完成设置。中断可重新打开「查看或继续设置恢复钥匙」继续。

日常备份钥匙保存在本机配置目录的 `backup-secrets` 中（目录权限 700，文件权限 600），只供程序运行备份使用。它不包含于资料库备份，不能把该目录当作应急恢复 JSON。云服务商 Access Key 用于访问存储桶，同样不替代解密钥匙。

导出文件是格式化的 UTF-8 JSON，可以打印保存。建议在支持文件权限的磁盘导出，再离线保管副本；文件权限应为 600。不要将明文恢复文件上传到备份所在的云目录。导出并不等于启用；任务失败或取消时，用同一份文件重试验证。不会删除已有备份或原密码。

本地与云端仓库分别设置，文件名默认带有目标与随机编号。更换仓库需重新设置；更换相同仓库的磁盘路径后可用原恢复文件重新验证。状态显示的是最近验证记录，不代表磁盘或云端此刻仍然可用。

## 手动备份包与 OneDrive（Build 22 起）

1. 停止服务并保存配置。首次使用时，通过本地备份向导建立加密仓库，保存并验证该位置对应的恢复 JSON。目录可以在本机磁盘，不强制外置硬盘，不需要 S3。
2. App → 备份设置 → 手动备份包 → 导出完整加密备份包。选择该仓库已验证的恢复 JSON，再选择 `.sricsbackup` 保存位置。
3. 程序验证私密资料可解密，创建最新数据库与原文件快照，完整读取检查仓库，流式打包并检查包内文件哈希与 ZIP CRC。成功后在 Finder 中选中备份包。
4. 手动上传到 OneDrive，或保存到 OneDrive 同步目录并等上传完成。每次导出一个独立完整包，包括仓库当前保存的历史恢复点，大小可能高于当前资料库。此功能不管理网盘历史、配额或上传状态，不直接调用 OneDrive API。
5. 恢复 JSON 单独离线保管，**不会放入包内**。它包含解密秘密，不要与备份包放在同一云目录。

从包恢复：新机器打开 App → 从备份恢复 → 存储类型“加密备份包” → 选择下载完整的包与匹配的 JSON → 选择导入位置 → 校验完成后选择恢复位置 → 恢复并校验。无需原机器、登录密码、保险库口令或 S3 凭据。默认提供本次导出的最新恢复点；旧恢复点仍完整保存在导入仓库中，如需旧版本，可选择“本地 / 独立硬盘”来源、导入目录下的 `repository` 与同一 JSON 读取历史。恢复完成后可删除加密导入副本，保留原包与 JSON。要启用恢复副本，可为它配置新的登录密码和保险库口令。

导出需额外预留一份加密仓库大小的磁盘空间。恢复时加密导入副本与恢复后的资料库分别占空间，选择位置前确认容量充足。支持流式 ZIP64、不额外压缩密文，单包限制 1 TiB、20 万仓库文件，校验清单最多 32 MiB。原有 WebP 和其他库内原文件逐字节保留。

包使用标准 ZIP64 / ZIP Store，扩展名 `.sricsbackup`，内部仅 `srics-package.json` 与 `repository/`，后者是完整 restic 加密仓库。清单保存格式版本、公开仓库 / 恢复点 / 密钥编号、时间、仓库文件大小与 SHA-256，不含用户文件名称和解密秘密。如果未来 App 不可用，可用标准 ZIP 工具解包，再按本文的 restic / age 手动恢复方法处理 `repository/`。

取消或失败不会发布未完成的包，不覆盖已有包；如果最终文件已成功写入但界面未收到完成回执，应保留该文件并用恢复入口验证。新快照和原仓库会保留。导入失败会清理本次新建副本；恢复阶段失败仍保留恢复目录供排查，不会启用未验证的资料库。

## 整机丢失后的恢复

1. 在新机器打开 App，选择「从备份恢复」。无须先创建资料库或记得旧登录密码。
2. 填写备份位置，选择解锁方式「恢复密钥」，选择保存的 JSON。云端还需要存储桶访问凭据；恢复密钥不代替云账号身份。
3. 读取历史，选择标记「支持所选恢复密钥」的恢复点，恢复到新目录并校验。
4. 可直接「取回单项文件」，普通原件与私密原件均可导出；小说导出 TXT，漫画导出 ZIP。
5. 要继续使用资料库，点击「配置恢复后的资料库」，为新副本设置登录密码与保险库口令，再启用。JSON 用于解开备份中的私密资料，新密码只配置到恢复副本；此操作不能作用于当前使用中的原资料库。
6. 重新配置独立的日常备份口令文件、云端连接等机器设置。恢复 JSON 继续离线保管，不作为日常备份口令文件。旧备份口令也已丢失时，可在恢复验收后配置一个新的备份仓库和独立口令，完成新备份后再处理旧仓库。

rc6 起，使用恢复文件恢复时，会在写入成功记录前实际解开私密索引，并校验私密原件及预览的完整内容，包括回收站中的私密条目。额外校验需要读取私密文件，资料量大时耗时更长；不会生成明文临时文件。密钥封装或内容校验失败会保留恢复目录供排查，但不记录恢复成功，建议选择其他恢复点。

日常自动备份仍在私密区锁定时工作，不保存你的恢复秘密；它检查索引结构、文件哈希和 restic 仓库完整性，无法代替拿出离线恢复文件进行的实际解密演练。结构正确但密文内部损坏的恢复记录，需要实际解密才能最终识别。

## 覆盖范围与旧密钥

- 只恢复所选快照当时已保存的内容，未备份的新增或修改不在其中。优先选择最近一次备份和完整读取校验都成功的恢复点。
- 漫画、图片、个人照片、小说、私密照片和个人文件均在恢复范围内；名称、标签和章节等索引随数据库恢复。小说可导出正文 TXT，文件类可导出库内原件，漫画可导出 ZIP。
- 导入时已无损转成 WebP 的漫画页，恢复的是库内保存的 WebP；不会还原导入前 PNG/JPEG 的原始编码文件。直接导入的 WebP 不重复压缩。本说明的“原件”指系统实际存储的原件，不能代替外部原始文件的独立归档。
- 仅包含对应恢复记录的快照支持完整应急恢复。启用前的历史快照不补写恢复记录；App 会标记并阻止将这些旧快照作为此密钥的完整恢复点。
- 后续手动、自动、更新前备份会继续携带恢复记录和公开密钥编号。修改日常私密区密码只是重新保护同一个加密身份，不会撤销恢复密钥。
- 如果生成时尚未启用私密区，之后新建了私密区，必须重新生成并验证密钥。旧密钥不能解开后来创建的私密区，新快照不会标记它为完整恢复密钥。
- 重新生成不会撤销以前导出的密钥。本版没有“一键撤销历史恢复文件”；掌握旧密钥和对应仓库副本的人仍能恢复旧资料。怀疑泄露时，不能仅改登录密码解决。
- 恢复文件丢失，但日常密码仍在，可以重新生成。所有有效口令与恢复文件全部丢失，仍然无法解密。

## 存储与兼容格式

恢复文件含格式版本、仓库 ID、资料库 ID、时间、公开指纹和 32 字节密码学随机秘密（base64url）。不保存原登录密码、原备份口令、原私密区密码或云账号凭据；秘密只导出到用户选择的文件，通过私有 stdin 管道交互，不进入日志或命令行参数。

restic 使用原口令添加一个受随机秘密保护的新仓库密钥，保留原密钥；文件可解锁同一仓库移动后的副本。实现采用 restic 标准 [多密钥机制](https://restic.readthedocs.io/en/stable/070_encryption.html)。

SQLite 的 `settings` 表中：

- `recovery-library-id`：资料库的独立公开编号。
- `recovery-key-<完整密钥编号>`：公开状态与 `wrappedVault`。后者是私密区 X25519 身份经 age scrypt、以恢复秘密保护的密文。数据库不保存恢复秘密。
- `recovery-key-active-local/cloud`：该目标最近一次管理的密钥编号。旧记录仍保留。

快照附带仅含公开编号的 `recovery-keys.json`，restic 快照的 `recovery-key:<编号>` 标签用于标记恢复覆盖范围。这些标记不提供任何解密能力。

如果未来 App 不可运行，可使用标准工具手动恢复：把 JSON 的 `secret` 提取到私密口令文件，用 restic 恢复对应仓库；从恢复的 `index.db` 查找 `recovery-key-<id>` 记录，将 `wrappedVault` 从 base64 解码为 age 文件，使用同一个秘密解开它，得到 X25519 身份，再用 age 解密 `private-objects/`。名称及对象关系在 SQLite/加密元数据中。此流程需要工具操作，保留本说明和代码可方便长期迁移。

## 验证

- 本地真实 restic：导出未验证不可解锁；错误私密区密码、导出位置越界/符号链接、覆盖已有文件、取消确认、外来密钥均被拒绝。
- 删除临时测试机器的资料库、配置与口令文件，移动备份仓库。rc5 的演练通过互相独立的管理命令进程，仅凭恢复文件列出恢复点、恢复资料库并导出全部六类资料；漫画 ZIP 内每页、图片、个人照片、私密照片及个人文件逐字节比对，小说核对正文。子进程没有旧进程内存中的解锁身份，也没有传入旧密码。
- 灾难恢复后为新副本设置登录及私密区密码并启用；无效配置不留下只改了一半的密码。日常重设接口拒绝恢复 JSON 与保险库字段。
- 验证原日常密码继续有效、重复登记不新增重复 restic 密钥、私密区改密后恢复密钥仍有效、后续快照保留标记。
- S3 协议测试环境：登记备用密钥、重复登记、仅用备用秘密恢复，云端对象不含明文文件名、内容或恢复秘密。真实云账号仍需用户配置后验收。
- rc6 故障注入：恢复记录畸形、缺失或丢失私密身份封装时不再静默生成备份；恢复封装损坏、私密明文与索引不一致、仓库数据块缺失时不写入恢复成功记录；备份读取校验失败保留上次成功记录并跳过历史清理。
