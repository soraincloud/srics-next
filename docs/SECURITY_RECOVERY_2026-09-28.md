# 2026-09-28 第三轮安全与应急恢复检查

范围：在 `3ef6b90`（rc4）基础上，重新检查会话与私密区锁定、备份前数据校验、损坏索引下的清理保护，以及整机和全部日常密码丢失后的恢复。修复版本为 **0.3.0-rc5**，数据库版本仍为 4，无新增迁移。部署目标为独立 Mac＋云端加密备份。

## 恢复结论

**只剩完整、未损坏的备份仓库和已验证启用的完整恢复 JSON，也能恢复相应快照的全部六类资料，包括私密照片和个人文件。** 不需要旧登录密码、旧备份口令、旧私密区密码或旧机器配置。快照必须包含这份恢复文件对应的恢复记录；不能用启用前的快照证明完整恢复能力。

本轮演练创建漫画、图片、个人照片、小说、私密照片和个人文件，验证恢复文件并备份，然后删除合成旧机器的资料库、配置及日常口令文件，移动备份仓库到新位置。恢复历史查询、资料库恢复、列表与各项导出分别由独立子进程执行，通过部署 App 使用的管理命令入口调用，没有传入旧密码或继承父进程内存中的解锁身份。

结果：六类资料均可列出和导出。漫画 ZIP 的每一页、图片、个人照片、私密照片和个人文件逐字节比对通过；小说正文检查通过。之后仍可设置新的登录和私密区密码并启用恢复库。该演练使用真实 restic 和临时本地仓库，**不代表已完成用户真实云账号或另一台 Mac 的验收**。

恢复条件：

- 保存整份 JSON，密钥编号和指纹没有解密能力。持有完整恢复文件与备份的人也能解开私密内容。
- 保留完整 restic 仓库，单独的 snapshots 描述文件不足以恢复。云端仓库还需云账号或访问凭据才能取回；如果仓库已完整下载到本地，就不需要云账号参与解密。
- 只覆盖快照时已备份的内容；无法取回未备份的新文件，或被永久删除、破坏且无其他副本的备份。
- 漫画导入时已转成 WebP 的页面，恢复的是库内 WebP，不是导入前 PNG/JPEG 的原始编码文件。直接导入的 WebP 按原字节保存。

详细设置和迁移方法见[独立恢复密钥](RECOVERY_KEY.md)。

## 新发现与修复

| 问题 | 修复前复现及影响 | 修复 |
| --- | --- | --- |
| 未完成的解锁请求在锁定后重新打开私密区 | 正确密码的解锁请求已读取请求体、仍等待口令处理时，另一个请求点击锁定；旧请求随后成功，重新安装解锁身份。需要已有登录会话及有效私密区密码，但违背显式锁定的结果。 | 为会话增加私密区版本号。锁定以及成功解锁均推进版本；解锁开始时记录版本，写回身份前再次比较，拒绝锁定前的旧请求。新发起的正常解锁仍可用。回归使用同步屏障稳定复现，无时间猜测。 |
| 对象去重掩盖相互矛盾的索引记录 | 同一原件同时被已完成上传和已发布条目引用。修改条目的 SHA 后，旧校验按对象 ID 去重，保留了上传中的正确 SHA，误判成功；清理也继续删除了合成孤立对象。 | 去重前核对所有引用的大小与 SHA，相同对象冲突时校验和清理直接失败；缩略图保留所有引用的并集。生产备份路径验证固定快照，异常时不会继续正常备份成功及随后保留清理流程。 |

新增回归 `TestLockInvalidatesAlreadyPendingUnlock`、`TestConflictingReferencesCannotPassVerificationOrCleanup` 均在修复前失败、修复后通过。故障注入仅针对临时合成数据；没有破坏、解密或改写真实私密资料。

## 风险边界及使用前检查

本轮进一步消除了两个已知问题，不能证明不存在未知漏洞，也不能承诺硬盘损毁、备份永久删除或密钥全部丢失仍能恢复。此前报告中关于强制杀死备份进程后 `staging` 残留、缺少外部失败通知、FileVault 解锁及用户登录前服务不运行的边界仍然存在。

真实云端尚未完成配置和验收；未测试目标机器实际断电、100 GB 真实资料负载或云账号防永久误删。本轮未重新做浏览器视觉验收。审查并不构成删除其他现有副本的依据。

作为唯一日常资料入口前，仍应完成：真实云端成功备份和完整读取校验；为该云端仓库生成并验证恢复 JSON、另存离线；保存云账号恢复办法；在另一台机器只用备份与恢复文件恢复并抽查各类文件。完成前保留源文件副本。
