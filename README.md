# SRICS Next

轻量个人资料库，用于局域网文件管理、独立加密保险库与可验证的加密备份。

**当前版本：0.3.0-rc6。六类资料、分块续传、回收站清理、加密备份保留与恢复、本机自启和更新前保护已接入。正式作为主资料库前，必须完成目标 Mac 与真实云端的恢复验收。**

新增[独立恢复密钥](docs/RECOVERY_KEY.md)：在部署 App 中生成、导出并验证；遗失日常密码后，可从备份取回普通与私密资料，并为恢复副本设置新密码。

本轮[安全与长期保存检查](docs/SECURITY_2026-09-28.md)修复原件读取校验、异常索引下的清理保护、慢请求阻塞、持续运行的 HTTPS 续期，并升级服务和随包备份工具的安全依赖。

[第二轮复查](docs/SECURITY_RECHECK_2026-09-28.md)另外修复空数据库被重建后误清理原件、恢复密钥临时文件残留、配置失败时只修改部分密码的问题。请使用 rc4 或更新版本。

[第三轮复查](docs/SECURITY_RECOVERY_2026-09-28.md)修复保险库锁定与未完成解锁请求的竞争，以及重复对象引用掩盖索引损坏的问题。已在删除旧机器资料及密码后，通过独立进程，仅用备份与恢复文件取回全部六类资料，包括私密内容。建议使用 rc5 或更新版本。

[第四轮复查](docs/SECURITY_FAILURES_2026-09-28.md)补强损坏恢复记录的处理：异常记录会停止备份，密钥确认和应急恢复会实际校验私密原件。备份缺失、读取校验失败和私密内容不一致的故障注入通过。请使用 rc6 或更新版本；恢复密钥解决口令丢失，不能替代独立备份。

本机程序（macOS）：双击 `dist/SRICS Next.app`，在窗口中设置登录密码、独立保险库口令、资料目录和可选备份配置，点击“保存并启动”。之后一键启动、停止或打开资料库。关闭窗口不会停止后台服务；网页只保留登录，没有密码创建入口。

从源码构建（当前机器架构，需要 Go 1.27.1 或支持自动下载该工具链的 Go、Node.js 22.12+ 或 24+、Python 3、Xcode Command Line Tools）：

```sh
brew install webp
./scripts/package-macos.sh
./start.command
```

程序包内含前端、Go 服务、cwebp、restic 及其动态库。构建完成后运行不需要 Go、Node.js 或 Homebrew；`start.command` 也可直接打开配置窗口。当前是本机构建、临时签名的开发包，尚未完成 Apple 公证或其他设备兼容性验收。

restic 从固定的 0.19.1 源码与 `scripts/restic/` 中的依赖清单构建，不修改系统 Homebrew。备份格式保持兼容；源码校验值、依赖和许可证随包附带。发布前运行 `bash scripts/check-security.sh`，分别扫描应用与备份工具，避免只检查主程序。

默认资料目录为 `~/Library/Application Support/SRICS Next/library`，已有资料和密码会沿用。完整操作与后台管理说明见 [本机启动程序](docs/LOCAL_LAUNCHER.md)。默认仅监听 `127.0.0.1`；局域网模式使用 HTTPS，首次访问需要安装、信任导出的公共证书，见 [M5 部署配置](docs/M5_DEPLOYMENT.md)。

运行 `./scripts/check.sh` 完成构建、静态检查、并发测试和恢复集成测试。打包后运行 `python3 scripts/check-launcher.py 'dist/SRICS Next.app/Contents/Resources/bin/srics'` 检查独立测试资料库的后台启停与登录。样本验证仍可从网页运行，或执行 `./bin/srics verify --report reports/new-report.json`；不会覆盖已有报告，也不读取真实资料。

开发协作约定：本仓库由个人维护，默认直接在 `main` 开发。每批改动完成相应检查后，提交并推送到 `main`，不额外创建开发分支或 PR；用户另有要求时再调整流程。功能与验收记录继续维护在 `docs/`。

界面参考 Lumoswitch Global 版的黑白对比、描边卡片与胶囊控件，支持浅色 / 深色切换。桌面使用侧边栏，手机使用底部导航。设计与交互约定见 [界面记录](docs/INTERFACE.md)。

当前可在本机程序中选择仅本机访问或局域网 HTTPS。漫画、图片和个人照片可以实际上传使用，小说支持章节编辑与阅读；私密照片与个人文件需使用独立保险库口令解锁。当前不配置云账号，也不读取旧 SRICS 数据。

面向个人单用户使用，短期原始文件规模不超过 100GB。运行结构控制为一个主程序、一个 SQLite 数据库、本地文件目录，以及随发布包附带的 restic 工具。

详细功能、默认规则和验收标准以 [功能需求文档](docs/FEATURES.md) 为准。该文档根据 2026-09-19 的最新需求整理。

开发前的最终默认值、实施顺序和验收要求见 [开发计划与最终约定](docs/DEVELOPMENT_PLAN.md)。需求已具备开工条件，先验证无损转换、加密存储与备份恢复，再按阶段完成六类业务。

业务分为六个入口，备份中心与设置作为辅助功能：

| 模块 | 第一版范围 |
| --- | --- |
| 漫画 | 文件夹上传、可设置名称、名称与标签搜索、第一页预览、阅读、整本 ZIP 下载；非 WebP 支持图片无损转为 WebP，已有 WebP 原样保存 |
| 小说 | 名称与标签搜索、新建小说、章节新增 / 编辑 / 删除 / 排序、独立阅读模式 |
| 图片 | 上传与下载、列表、随机照片墙；无需名称、标签和搜索 |
| 个人照片 | 原文件上传备份、简单列表、原件取回 |
| 个人私密照片 | 加密上传下载、解锁后的列表与随机照片墙 |
| 个人文件 | 加密保存、可设置名称、解锁后按名称搜索、下载与删除 |

六类内容在界面上分别展示，底层复用存储、上传与备份。标签仅用于漫画和小说。保险库保护个人私密照片与个人文件；前者与普通图片拥有各自独立的随机浏览池。照片和个人文件保留原始格式与字节。

第一版采用单用户账号；六类核心需求均属于第一版完整范围。

技术选型：

| 部分 | 方案 |
| --- | --- |
| 后端 | Go，提供登录、文件访问、任务调度与备份编排 |
| 前端 | Vue 3，构建产物嵌入主程序 |
| 数据库 | SQLite，仅保存索引、非敏感元数据、设置和任务状态 |
| 文件 | 本机直接连接磁盘上的文件目录，原件采用不可变版本 |
| 本地保险库加密 | age Go 库，使用标准文件格式 |
| 备份 | restic，增量、去重、加密和历史快照 |

运行时无需独立部署 Node.js、MySQL 或 Redis。漫画无损转换使用随发布物交付的 libwebp 能力。SQLite 不放在 SMB 网络共享上。缩略图按需生成，导入和校验通过有并发上限的后台任务执行。

保险库的设计约束：

- 内容、原始文件名、标题与备注均加密；普通索引只保存必要的随机标识与密文存储信息。密文大小、数量和访问时间等仍可能暴露。
- 每个文件单独加密；解密私钥由独立保险库口令保护，解锁后仅在使用期间保留于进程内存，超时或重启后重新锁定。
- 不生成明文磁盘缩略图，不记录敏感正文，不进入普通全文索引或浏览器离线缓存。
- 锁定期间仍可备份密文及受口令保护的密钥文件。
- 第一版由可信主机上的服务端解密，不承诺端到端加密或抵御已经被控制的主机。
- 局域网使用 HTTPS；原件、缩略图、预览与下载均需鉴权。上传的 HTML、SVG 等主动内容不得直接作为同源页面执行。

备份方案采用一份工作数据、一份云端加密备份及一份独立硬盘备份。云端候选为阿里云 OSS 或采用 S3 接口的 Backblaze B2；最终供应商、地域与预算待选定。同一块磁盘上的另一个目录不计为独立副本。

建议每天备份，重要修改后支持立即备份；保留最近 30 个每日版本和 12 个每月版本。定期执行仓库结构检查及数据读取校验，每季度做一次隔离恢复演练。页面分别显示备份成功时间和恢复验证成功时间。保留策略及周期是初始建议，需根据变化量、恢复需求和费用调整。

数据库与文件的一致性方案：

1. 导入文件先写临时位置，校验完成后原子发布，再提交索引记录。修改原件产生新版本，不原地覆盖。
2. 备份时短暂协调写入，使用 SQLite 一致性快照机制（M0 Backup API；当前资料库 VACUUM INTO）生成数据库快照，并固定对应的文件版本清单。
3. 对已固定的版本禁止清理，后台备份相同恢复点的数据库、文件、加密密钥文件、配置和版本清单。
4. 备份结束后释放版本引用；定期校验和实际恢复验证作为独立任务。不能将热拷贝数据库或上传完成直接视为可恢复证明。

可重建缓存无需备份。备份口令与保险库口令分开管理；备份口令通过主机安全凭据存储供自动任务读取，保险库口令默认不持久化。云账号恢复方式、备份解密材料和保险库恢复材料须有独立于该主机的保存途径。

部署目标暂按 Mac mini 优先设计，最终设备仍待确认：下载原生发布包、双击启动、完成首次配置向导、注册后台服务，之后通过浏览器访问。向导负责选择数据磁盘、创建账号与保险库、配置备份并验证首次恢复。后续可提供 Linux/NAS 单容器版本。需要人工解锁的加密磁盘及访问设备的首次证书信任配置，应明确呈现。

外置数据盘缺失或身份不符时应停止写入并报告，不能自动创建同名空目录继续运行。安装、更新和数据恢复必须是不同操作，安装或更新不得自动覆盖已有数据。

实施顺序与交付条件：

1. M0：工程骨架与技术验证，用测试数据走通无损 WebP、加密存储及备份恢复。
2. M1：基础登录、会话、文件落盘、上传任务、回收站与最小备份状态。
3. M2：漫画文件夹导入、名称标签、第一页预览、阅读、整本下载，以及普通图片列表与随机照片墙。
4. M3：小说章节编辑、冲突与修订处理、搜索与阅读，以及个人照片原件备份和简单列表。
5. M4：完整的个人私密照片与个人文件界面，包括加密名称、会话独立解锁与隐私验证。
6. M5：原生安装、首次配置、更新前备份、云端与独立硬盘备份，以及空机器恢复验收。

验收以空机器恢复为准：仅依靠发布包、云端备份和独立恢复材料，即可恢复资料库、核对文件校验值并解锁保险库。旧 SRICS 采用复制导入，核对文件和元数据并完成恢复演练后再切换。

仓库只保存代码、设计和不含秘密的配置示例。真实文件、恢复码、密码、私钥、数据库、备份仓库和恢复包均不得提交，即使本仓库是私有的。

参考资料：[SQLite 使用场景](https://sqlite.org/whentouse.html)、[SQLite Backup API](https://sqlite.org/backup.html)、[age](https://github.com/FiloSottile/age)、[restic](https://restic.net/)、[restic 存储后端](https://restic.readthedocs.io/en/stable/030_preparing_a_new_repo.html)。
